The **Decent Docs** framework refers to a combination of UI + Core + Content Source, Decent Docs is more of a mental framework and each layer can be a library on its own.

## Philosophy

Decent Docs was created to bring a more customisable experience for building docs, to be a docs framework that is not opinionated, **a "framework" that you can break**.

### Less Abstraction

While most frameworks are configured with a configuration file, they usually lack flexibility when you hope to tune its details.
You can’t control how they render the page nor the internal logic.

Decent Docs expects you to write code and cooperate with the rest of your software, it shows you how the app works and fully customisable, instead of a configuration file.

### Seamless Integration

Decent Docs integrates tightly with your React framework, bringing useful utilities and a good-looking UI.

For Next.js developers, you are still using features of App Router, like **Static Site Generation**. There is nothing new for Next.js developers, that everything is familiar to you.

### Composable UI

The only thing Decent Docs UI (the default theme) offers is **User Interface**. The UI is opinionated for bringing better mobile responsiveness and user experience.

Every layout ships replaceable [slots](/docs/ui/layouts/page), and components accept your own - see [Customize UI](/docs/guides/customize-ui) for the approaches.

### Server-first Approach

Traditionally, static site generators are **static**.

However, Decent Docs introduce a server-first approach powered by React Server Component.
With perfect server-client boundary, content becomes dynamic and interactive.

You can fetch data from server to display content, or integrate with CMS receiving realtime updates. It is always up-to-date and easy to maintain.

### Minimal

Decent Docs is maintained with care for the maintainability of codebase.

While we don't aim to offer every functionality people wanted, we're more focused on making basic features perfect and well-maintained.
You can also help Decent Docs to be more useful by contributing!

## When to use Decent Docs

Decent Docs is designed with flexibility in mind, it is not limited to certain usages.

- `@decentdocs/core` is a headless UI library for building docs.
- `@decentdocs/mdx` is a useful library to handle MDX content.

For most of the web applications, vanilla React.js is no longer enough.
Nowadays, we also wish to have a blog, a showcase page, a FAQ page, etc. In these cases, Decent Docs can help you build the
docs easier, with less boilerplate.

You can read [Comparisons](/docs/comparisons) if you're interested.

### Documentation

Decent Docs focuses on **authoring experience**, it provides a beautiful theme and many docs automation tools.

It helps you to iterate your codebase faster while never leaving your docs behind.
You can take this site as an example of docs site built with Decent Docs.

### Blog sites

Most React.js frameworks can already suffice the needs of a blog site.

Decent Docs provides additional tooling, including syntax highlighting, document search, and a default theme (Decent Docs UI).
It helps you to avoid reinventing the wheels.
